# AbsoluteJS Agent Exchange A2A Extension v1

Identifier: `https://github.com/absolutejs/agent-exchange/extensions/a2a/v1`

This required A2A profile carries an opaque Agent Exchange reference between an
authenticated requester agent and recipient agent. Protected values, signed
standing mandates, OAuth tokens, mailbox credentials, encrypted envelopes, and
full Agent Exchange requests never appear in A2A messages, artifacts, task
history, push notifications, or extension metadata.

## Negotiation

The server declares the identifier in `AgentCard.capabilities.extensions`. A
dedicated Agent Exchange endpoint declares it with `required: true`; a shared A2A
endpoint may advertise it as optional so unrelated skills remain usable. The
client activates it using the `A2A-Extensions` service parameter on every
operation that carries or retrieves Agent Exchange task data. The Agent Exchange
handler rejects a message unless both the service parameter and message extension
activate this profile.

Authentication and authorization remain protocol-layer responsibilities. An
A2A message is not identity evidence. The server must authenticate the caller
using the Agent Card's declared security scheme and resolve the opaque reference
under that caller before authorization or secret access.

## Request message

The client sends one `DataPart` with media type
`application/vnd.absolutejs.agent-exchange-reference+json`. The message:

- has role `ROLE_USER`;
- lists this extension identifier in `extensions`;
- uses the exchange ID as `contextId`;
- repeats only the exchange ID in metadata under this extension identifier; and
- contains the bounded safe reference produced by
  `toA2aAgentExchangeReference()`.

The reference contains no account reference, challenge identifier, credential,
secret, signed mandate, or envelope. The recipient resolves the complete request
from its trusted store and verifies that the authenticated actor, resolved
request, signed mandate, and reference agree exactly.

## Result

Successful execution returns a completed A2A task containing one redacted
receipt artifact. A receipt may include the exchange ID, completion time,
remaining mandate uses, status, and a previously leakage-checked destination
reference. It must never contain protected bytes or provider credentials.

Failed authorization uses an A2A failed or rejected task or an allowlisted
protocol error. Dependency error text and sensitive request fields are not
returned.

## Security requirements

- Production HTTP bindings use HTTPS and validate the server certificate.
- Agent Card discovery follows redirects only when the host explicitly trusts
  the new origin; the AbsoluteJS adapter rejects redirects.
- The caller's OAuth audience/resource and delegated actor identity are checked
  independently of this extension.
- Standing mandates are verified and atomically consumed before mailbox access.
- A2A task stores retain only the opaque reference and redacted receipt.
- Duplicate exchange IDs converge through the host's Agent Exchange replay and
  idempotency stores; A2A delivery alone never grants another use.

This profile follows the A2A extension and service-parameter model, RFC 9728
protected-resource metadata, RFC 8693 subject/actor separation, RFC 7515 signed
mandates, and RFC 8785 canonical signed payloads.
